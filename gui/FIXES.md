# 本轮修复与验证

## 问题对应

| 问题 | 修复 |
| --- | --- |
| 下载后「所在文件夹」打开位置不正确 | 使用 opener 的原生文件定位接口替代 `explorer /select,...` 命令行拼接；定位下载记录中的实际文件，兼容含中文、空格和逗号的文件名。 |
| 选择目录/Cookie 文件提示 `dialog.open not allowed` | 为 `main` 本地窗口声明 `dialog:allow-open`，同时授权前端事件订阅所需的 `core:default`。不为远程页面授权。 |
| 设置页切换大小跳动 | 固定外框高度，按视口限制，内容在内部滚动；保留刷新时的滚动位置和输入焦点。 |
| 选择路径/开关界面不刷新 | 立即更新对应控件，不再依赖无变化的渲染签名触发重建。 |
| 部分设置保存无效 | 后端持久化 audioFormat、playlistItems；空配置恢复默认，限制并发范围；音频选项随清晰度切换显示。 |
| FFmpeg 更新没有入口 | 设置中显示独立检查/安装按钮，调用正确的 FFmpeg 命令，更新后重新检测并刷新版本。 |
| FFmpeg 更新漏报/误报 | 托管版本优先，使用发布时间与资产摘要识别滚动构建；重复检查同一构建不再提示更新。 |
| 新 yt-dlp 未用于解析 | 解析与下载使用同一套托管运行时解析规则。 |
| 更新可能破坏旧版本 | 两个组件均先校验 SHA-256、试运行；FFmpeg 完整目录切换和失败回滚，保留 bin/lib、许可证；拒绝并发安装。 |
| Linux/ARM64 选错文件 | 按架构选择资产，不向 ARM64 回退发放 x64 yt-dlp；保留 shared 库相对路径。 |
| 解析超时后台进程遗留 | 独立 watchdog 终止超时的解析进程，阻塞工作放到后台线程。 |
| 代理敏感信息进入诊断 | 日志/诊断隐藏代理值，更新传输启用 SOCKS 支持。 |
| 安装包/开源准备 | NSIS/DMG/AppImage/deb 构建矩阵、独立 GUI CI、版本一致性检查、跨平台图标与打包许可证说明；沿用已有 Unlicense。 |

## 参考项目

- [Videdown main.ts](https://github.com/cshuangyy/videdown/blob/main/electron/main.ts)
  在项目目录、resources 目录、PATH 中查找二进制，用 Electron dialog 选择目录。
  它的 Electron 权限机制不能直接套到 Tauri；这里修复的是 Tauri 2 capability。
- [DownVid fetch/download.go](https://github.com/yxxbc/downvid/blob/main/backend/internal/fetch/download.go)
  将依赖下载到托管目录，校验摘要并重命名安装。
- [DownVid manifest.go](https://github.com/yxxbc/downvid/blob/main/backend/internal/manifest/manifest.go)
  使用固定清单版本与摘要，强调可复现性和平台映射。

这些项目也具有依赖管理能力。本项目本轮采用的方向是：直接查询上游最新发布、
向用户展示两个组件的当前/最新版本、明确失败状态，由用户点击更新；保留代理、
下载进度、完整性验证和回滚。没有复制它们的 Electron/Go 实现。

## 验证范围

- Windows Rust 单元和集成测试：55 项，包括本地 HTTP 媒体解析/下载。
- 实际联网在隔离目录安装 yt-dlp 与 FFmpeg，校验与试运行成功；再次检查两个组件均无更新。
- 浏览器 UI 检查：1180×800 深色、940×620 浅色，五个设置页宽高一致，路径反馈、开关、音频选项与两个更新入口通过。
- Tauri 构建生成的 ACL 已包含主窗口文件选择权限；本轮没有自动操作 Windows 原生文件选择对话框。
- Windows NSIS 本地构建；macOS/Linux 的配置需要在对应 CI runner 上继续验证。
- npm audit 已无已知漏洞。未执行远程 CI、未推送标签、未公开发布安装包。

## 0.3.2 Cookie 与画质

解析和下载统一采用 Cookie 文件优先于浏览器的规则，避免导入文件后仍因 Chrome 数据库占用而中断。
网络设置支持粘贴 B 站 Cookie 请求头（必须含 SESSDATA）或完整 Netscape cookies.txt，保存为本地文件；原始内容不进入 settings.json 或任务参数。
数据库占用、DPAPI 解密失败和文件格式错误给出可操作说明，解析弹窗可直接打开网络设置。
保留引擎的缺失画质提示；B 站解析展示当前会话的最高分辨率及登录/大会员限制。
同分辨率的编码、帧率、HDR 和码率选项不再被合并隐藏，取消格式数量截断。

BV1R1e4zKEh1 实测：未登录返回 360/480/720/1080p，yt-dlp 明确提示缺少 HDR、4K 和 1080p60，需要相应会员登录权限。
当前没有该视频的有效会员 Cookie，因此未验证登录后的 4K 下载；修复不会绕过站点权限，也不会把 1080p 标成 4K。

验证：66 项 Rust 测试通过（1 个子进程测试夹具忽略）；浏览器验证 Cookie 导入、网络设置跳转和画质说明，以及既有解析/设置/任务交互。

## 0.3.3 Windows 解析输出编码回归

0.3.2 为保留画质提示而开启普通日志，安装版 yt-dlp 在中文 Windows 上仍将日志编码为系统代码页，忽略 Python 环境变量。解析使用 read_to_string 且忽略读取错误，导致一条中文提示丢弃整段包含有效 JSON 的输出，界面只显示 returned no data。
修复：显式传递 yt-dlp 的 --encoding utf-8；按字节读取 stdout/stderr，再将日志与 JSON 分离，兼容旧编码日志。读取失败和输出超限明确报错，长日志保留最后的错误。
新增混合编码回归、读取失败/日志截断回归，以及托管 Windows yt-dlp 可执行文件的实际解析验证；原本只排除部分错误的本地媒体测试改为必须成功返回格式。
实测 BV1R1e4zKEh1：使用已安装的托管 yt-dlp，经生产 analyze_with 路径成功解析并保留 4K 权限提示。验证使用默认无 Cookie 配置，不读取用户登录信息。

完整验证：69 项 Rust 测试通过，1 个子进程夹具忽略。测试同时覆盖源代码引擎与托管可执行文件；修复了严格回归测试暴露的直链音频缺少 codec 元数据时无格式可选的问题。

## 0.3.4 抖音下载适配

复现视频 7685998763474799881：原 yt-dlp 详情接口返回 HTTP 403，然后统一报 Fresh cookies。
内置 Unlicense 抖音兼容插件（参考 viking1304 的 yt-dlp PR #17826），注册匿名访客会话并对详情请求签名。解析和下载、托管可执行文件和源码引擎共用插件，更新 yt-dlp 后保留适配；不使用第三方解析站点。
插件作为 Tauri 资源进入安装包，启动时使用当前平台 resource_dir 定位；开发和命令行诊断使用本地资源路径。
Cookie 粘贴支持明确选择 B 站/抖音，限制域名，拒绝把 B 站 Cookie 作为抖音 Cookie；添加新网站时保留原文件里其他网站的 Cookie。抖音失败时说明会话/接口拒绝与刷新方法，不将它一概归为必须登录。
所有引擎调用显式使用 --encoding utf-8，避免下载日志也触发中文编码问题。
实测：同一视频匿名解析成功；完整下载一条 720p HEVC + AAC 媒体，10,385,637 字节，ffprobe 校验时长约 319.95 秒。

验证：71 项 Rust 测试通过（1 个子进程夹具忽略）；使用 B 站域名的虚拟 Cookie 文件，通过生产解析路径成功解析该抖音视频；界面验证新增抖音 Cookie 导入。安装包只携带适配源文件，不打包 Python 缓存或 yt-dlp 二进制。

最终产物验证：0.3.4 release 可执行文件通过隔离配置（仅 B 站虚拟 Cookie）运行正式诊断下载路径，best 预设完整下载 22,279,354 字节的 1280×720 媒体，视频/音频轨道和 319.95 秒时长校验通过。NSIS 安装脚本确认包含适配插件并安装至 resource_dir 对应目录。
